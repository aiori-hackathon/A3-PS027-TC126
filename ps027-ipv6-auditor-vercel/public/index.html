How an audit runs

Six stages turn a domain name into a scored report.

  1. Resolve

    Query A and AAAA for the apex and www, plus NS and MX records.

  2. Crawl

    Fetch the home page and collect every host it loads scripts, styles, fonts and images from.

  3. Probe

    Open TCP 443 over IPv6 only, with a Happy Eyeballs fallback test against IPv4.

  4. Validate

    Check the TLS certificate and HTTP response served on the IPv6 path match IPv4.

  5. Simulate

    Repeat the fetch through DNS64 and NAT64 to model an IPv6-only network.

  6. Score

    Weight the eight checks, rank failures by impact and write the fix list.

System design

A web front end over a measurement service, so results come from live probes and can be reproduced.

Web UIThis site. Submits a domain, renders the report.
API gatewayValidates input, rate limits, queues jobs.
Probe workersDNS resolver, headless crawler and IPv6-only network namespace.
Scoring engineWeights checks, ranks fixes, stores history.
Report storeJSON results for trends and bulk comparison.

Data flow: the UI sends a domain to the API, which queues a job. Workers run the probes, the scoring engine builds the report, and the UI polls for the finished result. Optimisations: cached DNS answers, parallel probes per dependency and a shared crawl for repeat hosts.

Deployment timeline

Phase 1. DNS and HTTPS reachability checks for a single domain.

Phase 2. Dependency crawler and per-host IPv6 status.

Phase 3. IPv6-only simulation with DNS64 and NAT64, plus scoring.

Phase 4. Bulk audits, history and a public readiness dashboard.
